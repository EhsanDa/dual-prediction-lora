# firmware/node/ — the deployed node application

`main.ino` lived in `firmware/` from the start and **had never been compiled**.
It referenced seven hardware symbols that nothing implemented, and two of them
were not declared anywhere, so it failed at compile before the linker was
reached. This directory is that application, finished: the sketch, the radio
driver, the wire-format encoders, and the hardware layer underneath them.

Since 2026-09-28 it **compiles, links, runs on an ATmega328P, and reproduces
the Python reference byte for byte over 384 hours** — the whole application,
not just the codec.

```bash
make boards                    # which board is on which port
make node && make node-flash   # build and flash              (BOARD=1|2)
make node-run                  # replay the trace, diff against the reference
make node-deploy               # size without the bench instrumentation

make radio && make radio-flash # the two-board radio bench
make band-scan                 # which band are these modules built for?
make link-test                 # real frames across the air, decoded
make toa                       # measured airtime vs the Semtech model
```

## What is verified, and by what

| Claim | Proved by |
|---|---|
| the codec is byte-identical on the part | `../hil/` — `make -C ../hil hil-run` |
| **the application around it is too** | `make node-run`, against `node_expected.h` |
| the C wire format equals the Python | `tests/test_node_protocol.py`, 23 cases |
| the frames really cross the air | `make link-test`, both frame types, CRC-clean |
| the radio is configured as the model assumes | `make toa`, within 2.4 % of the Semtech formula |

**Two honest qualifications on the SRAM total.** The 335 B stack figure is
measured on the *bench* build; the deployed build takes the same deepest path
(`daily_boundary` → `codec_day_boundary`) so it is the same number, but it was
not measured on that build because that build has no UART to report it. And the
dataset replay stands in for a meter interface — there is no meter and there is
not meant to be — so a production build would swap `meter_trace.h` and
`meter_read_kwh()` for a sensor driver of its own size. That is the one thing
these rows still cannot account for, and it is stated rather than guessed.

— comfortably under. SRAM "under ~750 B" predicted, **≈879 B measured** —
**over, by about 130 B**, once the stack is counted. It still fits, at 43 % of
the part.

## The meter, which is not a meter

There is no meter attached and there is not meant to be: this project's input
is dataset data. `meter_read_kwh()` replays `meter_trace.h`, a PROGMEM copy of
the same inputs `golden_vectors.h` records, generated by
`export/gen_meter_trace.py`.

Because `SCALE_K` is negative, `kWh = u · 2^SCALE_K` is an exact binary
fraction and `quantise()` returns the integer it started from — so the
application can be compared against the reference rather than merely run.
**The kWh value itself is not physically meaningful** (the trace's own scale is
`k = -2` while `edge_config.h` ships `SCALE_K = -6`); only the integer round
trip matters, and it is exact. Nothing here should ever be quoted as an energy
reading.

Two details that cost a debugging cycle each, recorded so they are not
rediscovered:

- **The commissioning read does not advance the trace.** `u0` primes the ring
  (`edge/codec.py:269`); it is a prior, not an observation. Letting `setup()`
  consume `trace[0]` shifts every output by one hour.
- **The trace stores PRE-clamp values, as `int32`.** One hour carries a spike
  of 40 000 000 device units that `build_series` injects precisely so the
  quantiser clamp is exercised. Shipping the already-clipped value leaves that
  branch dead and costs exactly one flag bit at hour 260.

## Why `node_expected.h` and not `golden_vectors.h`

`golden_vectors.h` deliberately **drops the resync on day 5**
(`gen_golden.py`'s `skip_days = {5}`) so `test_host.c` covers `codec_new_day`
as well as `codec_day_boundary`. A node applies its day boundary
unconditionally (**note, 2026-09-28:** this is an *ungated* node — it is not the protocol the paper reports, where the node updates only on ACK; see `docs/findings/2026-09-28-frame-loss-settled.md` and card P3-08) — the resync carries the post-update weights and needs no ACK —
so it cannot reproduce the golden trace past hour 120 and should not be
expected to.

`node_expected.h` is the same reference codec over the same inputs with every
boundary applied. It agrees with `GOLDEN_UHAT` exactly for hours 0–119 and
diverges only from 120, which is the fixture checking itself. Both files come
out of `export/gen_meter_trace.py`; `make regen`.

## The radio

Raw point-to-point LoRa over SX127x. **Not LoRaWAN** — an LMIC stack needs
~1.5–2 kB SRAM and ~30 kB Flash and does not fit; there is one gateway per
building, so its join and addressing machinery buy nothing. See
`docs/reference/design-rationale.md:182`.

Settings match `edge/protocol.py`'s airtime model exactly, because a measured
airtime compared against a differently-configured model means nothing: SF12,
BW125, CR4/5, 8-symbol preamble, explicit header, CRC on, low-data-rate
optimisation (mandatory at SF11/12 on 125 kHz, and applied on the same
condition in both places).

**Three hardware facts that cost real time to find.** All three are in
`sx127x.c` at the line that depends on them:

1. **The PA must be on PA_BOOST, not RFO.** On RA-02, RFM95W and most SX127x
   breakouts the antenna is bonded to PA_BOOST and the RFO pin is not
   connected. Transmitting through RFO completes normally, sets TxDone, and
   radiates nothing — which looks like a receiver fault. `PaSelect = 1`,
   `OutputPower = 0` gives **+2 dBm**, the minimum the boost path offers.
2. **SPI reads are not trustworthy while the PA is keyed.** Polling
   `RegVersion` during a transmission returns `0xAA` instead of `0x12` for the
   whole ~1 s the frame is on the air. `0xAA` has bit 3 set, and bit 3 is
   TxDone — so a naive poll concludes the frame finished after one millisecond
   and drops the radio into standby. Every register read on that path is now
   guarded by a `RegVersion` check. Likely cause: the Uno's 3.3 V rail comes
   from the USB bridge's regulator and is marginal for PA_BOOST.
3. **DIO0 is not used.** The probe found a pin held low by the module on each
   board — D3 on board 1, D2 on board 2 — consistent with DIO0 but unconfirmed,
   and *different between the two boards*. Polling `RegIrqFlags` costs one SPI
   transaction and removes the question.

**Band: 433 MHz, measured, not assumed.** `make band-scan` transmits a few
frames at minimum power on each candidate band and reports what the other board
hears. These modules answer at −61 dBm on 433 and −65 on 470, and are silent on
868 and 915: they are 433 MHz parts (SX1278 / RA-02 class). Confirm 433 MHz is
licensed where the node will run before transmitting above the minimum power
used here.

## Two bugs fixed in `main.ino`

Neither is in any reported number; the paper never mentions this file.

- **`uint8_t pkt[80]` was too small for its own protocol.** A resync is header
  6 + payload (2 + 23 zigzag varints) + status 1 + bitmap 3 + `n_w` 1 + 4·N_W
  weight bytes + CRC 2 — about 83 B typically, which is the very figure Table II
  quotes for its airtime, and up to `RESYNC_MAX_BYTES` worst case. The buffer is
  now derived from the protocol, and `tests/test_node_protocol.py` pins both the
  bound and the encoder's refusal to overrun a short buffer.
- **`encode_resync` and `apply_downlink` were called with no declaration.** They
  now exist, in `node_protocol.c` and `node_hw.c`.

`send_exception` also no longer lays the eight bytes out by hand — it calls the
same encoder the gateway's format comes from, so there is one implementation
rather than two that can drift.

## What is deliberately not done

- **`sleep_until_next_hour()` returns immediately.** The trace is the clock;
  sleeping 3600 s per sample would make a 384-hour run take sixteen days.
  **Any energy figure from this build is meaningless** — card P3-01 step 3
  needs a build that really sleeps, on a board not powered through a USB bridge.
- **`CMD_CLOCK_CORRECTION` and `CMD_SET_N_MAX_TX` are accepted and not acted
  on.** The first needs an RTC the bench does not have; the second needs
  `N_MAX_TX` to be mutable, and it is a compile-time constant in the generated
  `edge_config.h`.
- **`make toa` is not card P3-01 step 4.** It validates that the driver is
  configured as the model assumes. Its own timing is a 1 ms polling loop with
  two SPI reads per iteration, which biases it low by about 2.4 % — visible as
  968 ms against a modelled 991. A real airtime measurement wants a timer
  capture, and is the author's to run deliberately.
